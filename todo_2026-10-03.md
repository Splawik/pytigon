# P0 — Bugs

## P0-1. `max-height` / `min-height` without `height` raises `IndexError`, element is dropped

- **Where:** `pytigon_lib/schhtml/basehtmltags.py:142-149`
- **Evidence:** `_norm_sizes_and_minmax` starts with `if size_str not in attrs: return []` (`basehtmltags.py:443`). Both `height` branches pass `"height"` as `size_str` while gating on `"max-height" in attrs`. Two lines above, the `width` branches correctly pass `"max-width"` / `"min-width"` — the `height` pair was copy-pasted and never updated.
- **Impact:** runs from `BaseHtmlElemParser.__init__`, i.e. **once per element per HTML parse**. `HtmlViewerParser._handle_starttag` wraps construction in `except Exception` and only logs `"Error handling start tag <...>"`, so `<div max-height="200">` is **silently omitted** from PDF/print output.
- **Change:**
  ```diff
  -            self.max_height = self._norm_sizes_and_minmax(
  -                self.attrs, "height", "max-height", None, self.get_parent_height()
  -            )[0]
  +            self.max_height = self._norm_sizes_and_minmax(
  +                self.attrs, "max-height", "max-height", None, self.get_parent_height()
  +            )[0]
  ```
  same for `min_height` (`"min-height"`).
- **Acceptance:** `<div max-height="200">` renders; add a regression test asserting no log entry.

## P0-2. Aliased column-width lists in `calc_col_sizes`

- **Where:** `pytigon_lib/schhtml/tags/table_tags.py:183`
- **Evidence:** `self.sizes = [[-1, -1, -1]] * self.col_count` — `list * int` replicates **one** object. The correct form appears 180 lines later for the same field: `table_tags.py:364` → `[[-1, -1, -1] for _ in range(self.col_count)]`.
- **Impact:** columns that never get rebound (all-`TdRef` rowspan cells, or all `colspan > 1`) share one list that is then mutated in place at `table_tags.py:224-225, 259, 267, 272, 276` (`pos[0] = ...`, `self.sizes[j+k][idx] += delta[idx]`). One colspan cell therefore writes its delta into every un-rebound column → **wrong column widths in PDF/print tables**.
- **Change:** `self.sizes = [[-1, -1, -1] for _ in range(self.col_count)]`
- **Acceptance:** existing table-rendering tests stay green; add a case with a `colspan` cell plus an unbound column.

## P0-3. Leaked loop variable puts the fixed width on the wrong `<td>`

- **Where:** `pytigon_lib/schhtml/tags/table_tags.py:384`
- **Evidence:** inside `if no_size_count == 1:` the widths are correctly applied to `self.sizes[no_size_id]`, but the next line calls `self.tr_list[-1][i].set_width(...)`. After the `for i in range(0, self.col_count)` loop, `i == self.col_count - 1` — **not** `no_size_id`.
- **Impact:** `set_width` pins the **last** cell of the row to a bogus fixed width; `_get_width()` then reports it as authoritative (`if self.width >= 0: return [self.width]*3`), corrupting `_row_height`.
- **Change:** `self.tr_list[-1][no_size_id].set_width(self.width - width_tab)`
- **Acceptance:** row heights of tables with exactly one auto-sized column match the pre-fix ones only where the two indices coincide; otherwise they become correct.

## P0-5. `GlobalBus.set_state` inverts its guard — changed values are silently dropped

- **Where:** `pytigon/pytigon/static_src/pytigon_js/component.py:297`
- **Evidence:**
  ```python
  if not (key in self.state and self.state[key] != value):   # docstring: "Only emits values that have actually changed"
      self.state[key] = value
      self.emit(key, value)
  ```
  | case | expression | effect |
  |---|---|---|
  | new key | `not(False)` → True | set + emit ✔ |
  | same value | `not(False)` → True | set + **re-emit** ✘ |
  | **different value** | `not(True)` → **False** | **nothing happens** ✘ |
- **Impact:** `window.GLOBAL_BUS` is instantiated in `static_src/pytigon_main.py:29`. Any consumer stops receiving updates from the **second** write to a key onwards.
- **Change:** `if key not in self.state or self.state[key] != value:`
- **Acceptance:** JS unit test for `set_state` covering all three rows of the table.

## P0-6. URL patterns: mutating the list while iterating skips every second `"../"` pattern

- **Where:** `pytigon/pytigon/schserw/urls.py:390`

## P0-7. `_serve_media` traversal check is a bare prefix test

- **Where:** `pytigon/pytigon/schserw/urls.py:222-230`
- **Evidence:** `if not fullpath.startswith(root): raise Http404(...)`. With `document_root = MEDIA_ROOT = <data>/<prj>/media`, request path `../media_secret/keys.txt` normalises to `<data>/<prj>/media_secret/keys.txt`, which **does** start with `<data>/<prj>/media` → served. `str.startswith` is not path containment, so any sibling directory whose name begins with the basename of `media` (`mediaX`, `media-backup`, `media2`) is readable.

- **Change:**

  ```python
      raise Http404("Path traversal detected")
  ```
- **Acceptance:** tests for `../media_secret/x`, `../mediaX/x`, and the legitimate in-root case.

## P0-8. Login endpoint is an open redirect

- **Where:** `pytigon/pytigon/schserw/schsys/urls.py:41-44`
- **Evidence:**
  ```python
  if not path.startswith("http://127.0.0.2") and not url_has_allowed_host_and_scheme(path, allowed_hosts={request.get_host()}):
      path = make_href("/")
  ```
  `startswith` matches the **string**, not the host, so `path = "http://127.0.0.2.evil.example/phish"` skips validation entirely, and `HttpResponseRedirect(path)` (`urls.py:76`) sends the freshly-authenticated browser to the attacker.
- **Change:**
  ```python

      path = make_href("/")
  ```
  (`request.get_host()` returns `host` or `host:port`; adding the bare loopback IP keeps the embedded `127.0.0.2` client working, because the helper compares `urlsplit(url).netloc`.)
- **Acceptance:** test `next=http://127.0.0.2.evil.example/` → redirects to `/`.

## P0-9. `truncate` filter: the `except` branch repeats the failing call

- **Where:** `pytigon/pytigon/schserw/schsys/templatetags/exfiltry.py:208-219`
- **Evidence:**
  ```python
  try:
      retstr = str(value)
  except Exception:
      retstr = str(value)        # the exact call that just raised
  ```
  The guard is dead code — the exception always propagates. Additionally `int(arg)` is evaluated twice and is unguarded, so `{{ v|truncate:"ten" }}` raises `ValueError` out of the template.
- **Change:**
  ```python
  retstr = str(value)
  try:
      maxlen = int(arg)
  except (TypeError, ValueError):
      return value
  if len(retstr) > maxlen:
      return retstr[: max(0, maxlen - 3)] + "..."
  return retstr
  ```
- **Acceptance:** filter tests for short/long values, `arg < 3`, and non-numeric `arg`.

## P0-10. `--listen=` parsing: truncation and `ValueError` on IPv6

- **Where:** `pytigon/pytigon/commands/handlers/runserver.py:73-82`
- **Evidence:** `listen = item.split("=")[1]` truncates a value containing `=`. Then `address, port = listen.split(":")` — for `--listen=[::1]:8000` this yields 4 parts → `ValueError: too many values to unpack` and the whole `runserver` command dies. `settings/infra.py:259-262` already solves exactly this for `CHANNELS_REDIS` with `rpartition(":")` plus a comment explaining why. Also `_PORT_DEFAULT` is declared at `runserver.py:15` and **never used** — the literal `"8000"` is hardcoded at lines 69, 80, 146, 149, 151.
- **Change:**
  ```python
  listen = item.partition("=")[2]
  if ":" in listen:
      address, _, port = listen.rpartition(":")

      address = listen
      port = _PORT_DEFAULT
  ```
  and use `_PORT_DEFAULT` at the other four sites.
- **Acceptance:** `ptig runserver --listen=[::1]:8000` starts; a unit test over the parse helper.

## P0-12. One cell edit fires two identical synchronous HTTP POSTs

- **Where:** `pytigon_gui/guictrl/grid/grid.py:149-150` + `246-260`
- **Evidence:** the same handler is bound to **both** post-commit and pre-commit events:

# P1 — Performance on hot paths

## P1-1 **[measured]** `str(bytes)` twice per HTTP response

- **Where:** `pytigon_lib/schhttptools/httpclient.py:343-348`
- **Evidence:** `self.content` is `bytes` (set at `httpclient.py:329`). The guard runs `"Traceback" in str(self.content) and "copy-and-paste" in str(self.content)` — two full `b'...'` **repr** materialisations of the whole response body, merely to run two substring searches that `bytes` supports natively.
- **Measured** (2 MB body): `str` form **8.53 ms** → `bytes` form **0.82 ms** (**~10×**, ~7.7 ms saved per large response).
- **Change:**
  ```python
  if (
      self.ret_content_type
      and "text/" in self.ret_content_type
      and isinstance(self.content, bytes)
      and b"Traceback" in self.content
      and b"copy-and-paste" in self.content
  ):
  ```
  (`isinstance` also makes the guard safe when `content` is already `str`.)
- **Acceptance:** existing error-detection test still fires.

## P1-2 **[measured]** O(n²) menu dedup → `set`

- **Where:** `pytigon/pytigon/schserw/schsys/app_manager.py:203-214`
- **Evidence:** `ret` is scanned linearly for every item. `get_apps` is reached twice per render from `base0.ihtml` via `get_apps_width_perm`, four times from `tablet_base.ihtml`.
- **Measured:** 800 entries **3.30 ms → 0.05 ms (69×)**; 200 entries **219 µs → 11 µs (20×)**; 50 entries 18.6 µs → 3.0 µs.
- **Change:**
  ```python
  def get_apps(self, prj=None):
      ret = []
      seen = set()
      for item in self.get_app_items(prj):
          if item.app_name not in seen:
              seen.add(item.app_name)
              ret.append(item.get_app_info())
      return ret
  ```
  (order-preserving, so the rendered menu order is unchanged)
- **Acceptance:** `app_manager_test.py` unchanged and green.

## P1-3. `get_menu_id` recomputes `appid()` once per menu entry

- **Where:** `pytigon/pytigon/schserw/schsys/app_manager.py:216-223`
- **Evidence:** `self.appid()` (`app_manager.py:189-198`) does `request.path.split("/")`, `django.urls.get_script_prefix()` and `.count("/")` — loop-invariant, recomputed for every menu entry, then compared against a value that never changes. Called from `templates_src/js/desktop_base.ihtml:13`, `theme/to_print_base.ihtml:69`, `js/to_print_base.ihtml:13`.
- **Change:**
  ```python
  def get_menu_id(self):
      appid = self.appid()
      for i, app in enumerate(self.get_apps_width_perm()):
          if app.app_name == appid:
              return i
      return 0
  ```

## P1-4. O(n·m) insertion scan when assembling menu items

- **Where:** `pytigon/pytigon/schserw/schsys/app_manager.py:275-289`
- **Evidence:** the full `ret` list is rescanned for every `AdditionalUrls` entry. Two secondary defects in the same block: `id` **shadows the `id` builtin**, and `for pos in ret:` **shadows** the enclosing `for pos in urls2:` loop variable (`app_manager.py:256-289`) — the classic signature of a reused variable.
- **Change:** rename to `insert_at` / `existing`, iterate with `enumerate`, and `break` on an exact `module_name`+`app_name` hit (preserves "last matching index wins" for the partial match while stopping the scan on a full one).
- **Note:** the `break` makes the *first* exact hit win where the original could be overwritten by a later index — decide deliberately, or keep scanning and only rename. Pairs naturally with P1-2 in one commit.

## P1-5. `importlib.import_module` per permission-bearing menu item, per render

- **Where:** `pytigon/pytigon/schserw/schsys/app_manager.py:27-36`
- **Evidence:** `has_user_perm` re-splits the dotted path and calls `importlib.import_module` on **every** call — from `get_app_items_width_perm` (`app_manager.py:320, 332`), so once per menu item per render. Even on a cache hit that walks `_bootstrap._gcd_import` (module-name normalisation + `sys.modules` + the import lock). `functools` is already imported at `app_manager.py:1`.
- **Change:**
  ```python
  @functools.lru_cache(maxsize=None)
  def _resolve_perm_fun(fun_path):
      module_path, fun_name = fun_path.rsplit(".", 1)
      return getattr(importlib.import_module(module_path), fun_name)

  def has_user_perm(user, perm):
      if "|" in perm:
          arg, fun_path = perm.split("|", 1)
          return _resolve_perm_fun(fun_path)(user, arg)
      return user.has_perm(perm)
  ```
- **Acceptance:** permission tests green; confirm the cache warms after the first render.

## P1-6. `login_required(view_func)` rebuilt on every request

- **Where:** `pytigon/pytigon/schserw/schsys/urls.py:106-113`
- **Evidence:** `login_required(view_func)` is a decorator **factory**. Calling it inside `wrapper` allocates two fresh closures and re-reads `settings.LOGIN_URL` on every request. It wraps `datedialog`, `listdialog`, `treedialog`, `tabdialog`, `plugins`, `app_time_stamp` and `search` (`urls.py:128-145`) — i.e. all dialog AJAX traffic. The decorated view is a constant of the definition.
- **Change:**
  ```python
  def login_required_for_non_public(view_func):
      protected = login_required(view_func)

      def wrapper(request, *args, **kwargs):
          if settings.PUBLIC:
              return view_func(request, *args, **kwargs)
          return protected(request, *args, **kwargs)

      return wrapper
  ```

## P1-7. User-agent classification runs 3× / 2× / 2× per render

- **Where:** `pytigon/pytigon/schserw/schsys/context_processors.py:168-202, 301-311, 334-345`
- **Evidence:** `sch_standard` is registered in `TEMPLATES[0]["OPTIONS"]["context_processors"]` (`features.py:54`), so it runs on **every render**. Per render: `standard_web_browser(request)` **3×** (`context_processors.py:335`, plus once inside `browser_type` at :184 and once inside `client_type` at :169), `test_mobile` **2×** (:170, :185), `test_tablet` **2×**. `test_mobile` runs `_MOBILE_USER_AGENTS_RE` (`context_processors.py:97`) — a `|`-alternation of **65 escaped UA substrings**.
- **Measured:** 5.03 µs per regex search → **10.1 µs per render** spent on the duplicate pair alone. Modest, but it is unconditional work on the hottest path in the framework.
- **Change:** give `client_type` / `browser_type` / `_extract_browser_info` an optional `standard` parameter and thread the value already computed at `context_processors.py:335` into them. Keep the parameters optional so the existing tests that call `client_type(request)` (`tests/test_context_processors.py:106`, `tests/schserw/schsys/context_processors_test.py:106`) keep passing.
- **Acceptance:** both context-processor test files green; assert `standard_web_browser` is entered once per render with a counting stub.

## P1-8. `login_providers` resolves the adapter inside the loop

- **Where:** `pytigon/pytigon/schserw/schsys/app_manager.py:356-366`
- **Evidence:** `adapter = get_adapter()` is loop-invariant and re-resolved from the app registry on every iteration. Worse, `templates_src/base_base.ihtml` calls `app_manager.login_providers` **twice** per render (line 44 in an `% if`, line 49 in a `% for`), so the whole provider loop — including `adapter.get_provider(None, key)` per provider — runs twice just to test truthiness and then iterate.
- **Change:** hoist `adapter = get_adapter()` above the loop. Optionally follow up with a module-level `@functools.lru_cache(maxsize=1)` on the body (the provider map does not change at runtime) — slightly larger, so not bundled here.

## P1-9. `copy.deepcopy({})` + `re.sub` for every HTML element

- **Where:** `pytigon_lib/schhtml/css.py:40-49` and `187-191`
- **Evidence:** `get_dict` builds a throwaway `CssPos([""], {})` whose only purpose is to carry `parents`, but `__init__` first runs `superstrip("")` (a regex substitution) **and** `copy.deepcopy({})`, which walks the whole `copy` machinery (memo dict, `_deepcopy_atomic` dispatch) to copy an empty dict. `BaseHtmlElemParser.__init__` (`basehtmltags.py:105`) calls it **once per element**, and `p_tags.InlineElements.__init__:43` calls it a second time with `:hover`.
- **Change:**
  ```python
  self.attrs = copy.deepcopy(attrs) if (len(line) == 1 and attrs) else {}
  ```
  Behaviour-identical, because `deepcopy({}) == {}`. (The in-code comment explaining the deepcopy stays valid — the non-empty path is untouched.)
- **Acceptance:** CSS-resolution tests green.

## P1-10. `get_style_id` linear-scans the distinct-style list per element

- **Where:** `pytigon_lib/schhtml/dc_info.py:67-74`
- **Evidence:** `BaseHtmlElemParser.get_style_id()` (`basehtmltags.py:224-276`) builds a fresh `"{color};{family};{size};{italic};{bold};{underline}"` string per element and calls this. With *k* distinct styles and *n* elements the render is O(n·k) string comparisons. `self.styles` is also part of the serialised DC state (`basedc.py:142-143`), so the list must stay.
- **Change:** keep the list, add a parallel dict (`self._style_ids`) built lazily inside `get_style_id` or initialised in `BaseDcInfoCommon.__init__`. Impact scales with distinct-style count (low for typical 5–20 style documents, high for generated reports).

## P1-11. `get_action_parm` is a pure lookup called ~8× per row

- **Where:** `pytigon_lib/schtools/href_action.py:154-179`, called at `:326, 333, 336, 343, 349, 356, 361, 367, 374`
- **Evidence:** `STANDARD_ACTIONS` is a module constant and the function is pure (returns an immutable `str`). `Action.__init__` calls it for `title`, `icon`, `target`, `class`, `class_in_menu`, `attrs`, `attrs_in_menu`, `url` — and `Action` is constructed **once per action per table row** via `actions_dict()`. Every row re-does the same `action.split("-")`, the same dict lookups and the same `strip()`/`split("|")` inside `unpack_value`.
- **Change:** `@lru_cache(maxsize=2048)` on `get_action_parm`. Strings are immutable, so sharing the returned object between `Action` instances is safe; callers that post-process (`.replace("{{btn_size}}", btn_size)`) already produce new strings.
- **Acceptance:** href_action tests green.

## P1-13. `_flush_buffer` uses O(n) `list.remove` while reverse-iterating

- **Where:** `pytigon_lib/schindent/indent_style.py:465-476`
- **Evidence:** `list.remove(pos)` rescans from index 0, so flushing *k* entries out of an *n*-entry buffer is O(k·n); it is called once per source line from `transform_line`, and the buffer grows with template nesting depth. Secondary concern: `remove()` deletes the **first equal** element, not the one at the current reverse position, so duplicate `[indent, close_tag, status]` triples (exactly what nested identical tags produce) can be emitted in the wrong order.
- **Change:**
  ```python
  def _flush_buffer(self, min_indent: int) -> None:
      buf = self.buffer
      idx = len(buf) - 1
      while idx >= 0 and buf[idx][0] >= min_indent:
          self.output.append(buf[idx])
          del buf[idx]
          idx -= 1
  ```
- **Acceptance:** template-compilation output byte-identical for the `.ihtml` corpus under `pytigon/templates_src/` (do this as a before/after diff, not via unit tests).

## P1-14. `get_client_width()` evaluated twice per top-level block; it can trigger a full table height pass

- **Where:** `pytigon_lib/schhtml/tags/block_tags.py:188-198`
- **Evidence:** `self.get_client_width()[0]` appears three times in one expression. `BodyTag.get_client_width` → `get_height()` → `calc_height()`, and for a `<table>` child that is `TableTag.calc_height` → `_calculate_rows_height()` (a pass over **every** row, calling `get_height()` on every cell) plus `self._iter()`. Evaluated twice per top-level child whenever `max_width` misses the first branch — the common case for full-width blocks.
- **Change:** assign `client_width = self.get_client_width()[0]` once before the `while cont:` body. Behaviour is identical, including the side effect that the first call may trigger `render_new_page()`.

## P1-15. `<ul>` / `<ol>` child registration is O(n²)

- **Where:** `pytigon_lib/schhtml/tags/p_tags.py:403-412`
- **Evidence:** `self.children` is a plain `list` and `child not in self.children` uses `==` (identity here), so registering *n* `<li>` items performs 0+1+…+(n−1) comparisons. The sibling code at `p_tags.py:423-427` appends the same children to the parent `<ul>` too, so the list really does reach the full item count.
- **Change:** keep the list (order-sensitive, read elsewhere) and add an identity set `self._children_ids`, populated in both branches.

## P1-16. GUI: local icon files decoded from disk on every call

- **Where:** `pytigon_gui/guilib/image.py:198-221` (`bitmap_from_href`, no cache at all) and `136-152` (`bitmaps_from_art_id`)
- **Evidence:** `bitmap_from_href` has **zero** caching. It is called from `ERRORLIST.__init__` (`display.py:163`, `client://status/dialog-error.png`) — once per control instantiation on every page parse — from `SchGridPanel._get_bmp` / `_add_action` (`gridpanel.py:50, 72, 74`), from `ArtProviderFromIcon.CreateBitmap` (`image.py:314`) and from every `_ButtonClass._set_bitmap` (`button/base.py:203`). Each call is an `open()` + `read()` + PNG decode + `wx.Bitmap` conversion. Separately `bitmaps_from_art_id` is called ~19× with constant `(32, 32)` + constant `wx.ART_*` ids from `standardtoolbarbuttons.py:358-527`, and each call does a bitmap→image conversion, a full greyscale pass and a 4-channel adjustment.
- **Change:** add a module-level `@lru_cache(maxsize=512)` helper returning `wx.Bitmap(wx.Image(path))` and route the three disk branches through it; add `@lru_cache(maxsize=128)` to `bitmaps_from_art_id` (converting `size` to a tuple first so it is hashable). `wx.Bitmap` is copy-on-write, so sharing instances is safe.
- **Acceptance:** measure page-parse time before/after.

## Not applied

### P2-5 — `unindent()` first-non-empty vs minimum indent — **reverted, needs a decision**

The one-line fix (`next(...)` → `min(..., default=-1)`) is correct per the docstring
("Remove **common** leading whitespace") and it does fix real content loss
(`["    deep", "  shallow"]` yields `["  deep", "shallow"]` instead of `["deep", "hallow"]`).
It was implemented, then reverted, because an existing test explicitly pins the current
behaviour:

```python
# tests/schindent/indent_markdown_extra_test.py::TestUnindent
def test_mixed_indent_uses_first_nonempty(self):
    result = unindent(["    deep", "  shallow", ""])
    assert result[0] == "deep"
```

The docstring and that test disagree, so this is a **contract decision, not a bug fix**.
Changing a passing test to match new code is exactly how regressions get hidden, so the
call is left to the maintainer. The bug is reachable: `IndentMarkdownProcessor.convert`
(`schindent/indent_markdown.py:433-442`) appends `line[in_func_indent:]` for every line
whose indent exceeds the block indent, and those indents can differ within one block.

To apply it later, change both the function and that one test assertion.
